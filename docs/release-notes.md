# 更新记录

## v1.3.0 · 自动化采集与界面修复

### 新功能

- 新增自动化任务页面：每项任务独立设置商品类型、查询值、匹配方式、国家、店铺、运行星期与时间。
- 支持今天、昨天、近／前 7 天、近／前 30 天、本周、上周、本月、上月和固定日期区间；动态日期在每次执行时重新计算。
- 支持多任务并发，不设置任务数或并发数量上限；独立 Chrome 会话读取已有登录态，分别保存结果和日志。
- 启用系统定时后，关闭主窗口仍可执行；电脑需开机、当前用户已登录且未休眠，错过的计划分钟不补跑。
- 支持单项立即运行、全部启用任务同时运行、任务编辑／停用／删除、运行记录与历史结果查看。
- 新增“重置页面”，清空当前手动查询条件和结果展示，保留登录态、历史文件及已保存任务。

### 修复

问题现象、根因、修改和回归验证详见 [2026-11-14 Bug 修复记录](bugfix-log.md)。

- Windows 界面向采集管理进程发送任务时，明确使用无 BOM 的 UTF-8，修复中文名称、品名、国家及店铺在保存、编辑时被系统默认编码损坏的问题。
- 后台状态刷新不再临时禁用操作按钮；刷新期间仍可提交操作，过期的刷新响应不会覆盖操作结果。
- 任务和运行数据未变化时保留现有表格，避免周期性重建影响选择和编辑。
- Windows 日期选项只展示中文名称，不再显示内部键值对。
- Windows 界面自检增加中文完整保存、编辑回填、日期选项实际显示、刷新期间按钮状态及保存操作检查。Mac 同步修改刷新逻辑，发布自检覆盖自动化任务保存、立即运行的缺少登录态提示和删除流程。

### 安装与升级

- 下载 `lingxing-search-1.3.0-windows-x64.zip`、`lingxing-search-1.3.0-mac-arm64.zip` 或 `lingxing-search-1.3.0-mac-x64.zip`，按系统与芯片选择；随包提供 SHA256 校验文件。
- 升级前暂停定时运行，等待正在采集的任务结束并关闭应用；Windows 更新程序文件时保留自己的 `results/` 和 `.private/`，Mac 替换应用时保留用户数据目录。完成一次手动验证后再重新启用定时。
- 旧版已经保存损坏的内容需要重新填写正确字段再保存；更新程序不代表丢失的文本可以自动恢复。
- Windows 需要 .NET Framework 4.8 / 4.8.1 和 Chrome；Mac 支持 macOS 13+，需要 Chrome，仍采用 ad-hoc 签名，未经过 Developer ID 签名或公证。
- 发布前由工作流执行三平台构建、自检、解压后检查和校验值核对。云端不使用真实领星账号；Mac 的真实账号采集与本机系统定时需由使用者验证。

## v1.2.2 · Windows 与 macOS

- 普通采集不再保存完整网络记录或自动保存爬虫模板，保留必要登录态和正常业务报表。
- `--save-template` 主动启用爬虫模板，过滤 Cookie 及无关请求头；模板仍包含身份令牌，仅限本机保存。`--diagnostics` 仅保存请求路径、状态与数据结构摘要。
- 采集开始时移除旧模板和旧网络记录，不删除历史报表与登录态。
- 两端从同一国家列表读取 22 个候选，仍可手动输入。
- Windows EXE 的版本由 package.json 生成；新增 GitHub 自动编译、打包前自检、解压后自检与 SHA256 校验。
- Mac 增加 `--collect-once` 实际账号采集回归入口，自动输出测试报告和退出码。首次登录仍由使用者在专用 Chrome 中完成。
- 普通提交只生成构建产物，版本标签与 package.json 一致且三种平台包检查全部通过后才发布；不会自动覆盖已有 Release。

Windows：解压 `windows-x64.zip`，双击「商品诊断.exe」，需 Windows x64、.NET Framework 4.8/4.8.1 和 Google Chrome。

macOS：按芯片下载 `mac-arm64.zip` 或 `mac-x64.zip`，将 .app 拖到应用程序。需要 macOS 13+ 与 Google Chrome。当前为 ad-hoc 签名，未经过 Apple Developer ID 签名或公证。

构建机执行合成数据自检和应用启动检查，不登录实际领星账号；实际采集需在自己的电脑验证。JSON 结果格式保持兼容。
