# 本次会话整理（脱敏版）

## 目标与范围

计划制作「商品诊断」和「店铺检查」两个工具，本次完成商品诊断工具。用户希望减少 AI 逐步操作领星浏览器的过程，通过固定脚本获得商品报表，交给 AI 分析。

账户未开通付费官方 API，采用用户正常登录后的浏览器会话。浏览器版通过 Playwright 操作领星界面、监听业务响应并保存 JSON；直连版复用实际观察到的只读请求模板，用于同条件数据和耗时对比。

## 功能演进

1. 构建浏览器与直连两条取数路线，核对商品、日期、行数、字段结构与业务响应哈希。
2. 增加双击启动、标识类型、日期输入，并修复登录态保存、结果核验与退出码导致的误报。
3. 增加品名、模糊搜索、国家和店铺筛选；查询前重置旧条件，匹配多页时继续采集。
4. 解释输出格式：一组采集产生查询记录与业务数据两个文件；父 ASIN 汇总可关联多个款式与 MSKU。
5. 为内部字段提供中文释义，明确尚未核实的内部 ID 与计算口径。`null` 来自本次领星响应，可能受维度、未设置资料或数据源影响，不能直接补零或认定商品没有数据。
6. 用户选择深色背景、蓝色强调色和侧栏加卡片布局。新增采集条件、结果、历史、日志四个页面；只展示实际取得的数据。
7. 将 PowerShell 界面控制迁移为 C# / WPF 编译的 EXE。EXE 直接启动界面和随附 Node 采集进程；PowerShell 仅保留为开发构建工具和早期源码。
8. 验证启动、界面导航、输入校验、历史读取、中文参数及一次真实浏览器采集。公开版本重新使用占位符与合成数据构建、验证，不携带真实测试材料。
9. 明确其他 AI 的读取方式及 Windows 迁移方法，说明当前 Windows EXE 不能直接在 Mac 运行。

## 已确定的数据原则

- 退货率与退款率分别展示，不能混用。
- 空值保留为缺失并显示为「—」，真实的零保持为零。
- 每次采集的商品、国家、店铺、日期与原始响应共同保存。
- 金额显示当前记录币种，不默认把跨币种数据相加。
- 时间段汇总没有逐日序列时，不生成虚构趋势图。
- FBA 可售、其他库存状态与可用库存不是可直接相加的独立总量。

## 当前未完成的扩展范围

店铺检查、Mac 原生应用、逐日趋势、独立退货原因报表以及更完整的商品诊断建议尚未实现。本仓库保留扩展所需的清晰源码结构。
