# 自动化任务

在侧栏打开「自动化任务」，填写任务名称、商品标识、匹配方式、国家与店铺，再选择日期范围、运行星期与时间。默认星期为周一至周六，时间为 09:00；这只是编辑器默认值，保存前不会创建任务。

每个任务可以设置不同的星期、时间与筛选条件。「使用当前采集条件」会复制采集页的条件和固定日期；若希望日期自动向前滚动，复制后请改选动态日期范围。

保存任务后，点击「启用定时运行」。Windows 会注册当前用户的计划任务，Mac 会注册当前用户的 LaunchAgent，每分钟检查一次到期任务。关闭主窗口后仍可执行；电脑必须保持开机、已登录且未休眠，Chrome 需要已安装。使用电脑本地时区。错过的分钟不补跑；暂停后也不会补执行过去的任务。

「暂停定时运行」停止后续定时触发，已经开始的采集继续完成。「立即运行选中任务」与「同时运行全部启用任务」不受定时总开关影响。编辑或删除任务不会中断已启动的那次采集。

## 日期范围

- 今天、昨天：对应本机日历日期；今天的数据可能不完整。
- 近 7 / 30 天：包含今天。
- 前 7 / 30 天：截至昨天，不包含今天。
- 本周：本周周一至今天；上周：上一个完整周一至周日。
- 本月：本月 1 日至今天；上月：上一个完整自然月。
- 固定日期区间：每次都使用填写的相同起止日期。

动态日期在每次触发时计算；例如每周一采集「上周」，会读取刚结束的周一至周日，而不是永久保存创建任务那天的日期。

## 并发与登录

程序不设置任务数和并发数上限。到期任务会全部发起，每次运行使用独立 Chrome 进程与浏览器上下文，不共用正在运行的专用 Chrome 配置目录。实际能同时完成多少取决于电脑内存、CPU、网络和领星服务；资源不足、账号登录限制或服务拒绝会作为失败记录显示。

自动任务只读取手动采集保存的 Cookie、localStorage 与 sessionStorage，不覆盖共用登录文件和私有请求模板。首次使用请在采集条件页手动完成一次采集。登录过期时，运行记录提示重新手动登录并采集，再重跑失败任务。自动采集保持有界面的 Chrome。

## 结果与排错

每次采集仍写入 `results/browser-*.json` 与配对的业务数据文件，可在原有「历史记录」和自动化运行记录中查看。每个并发结果名增加唯一标识，避免同毫秒完成时互相覆盖。

任务配置和运行记录位于数据目录的 `.private/automation/`，其中 `tasks.json` 为配置，`runs/` 为运行记录，`logs/` 为每次运行的日志。一个任务失败不取消其他任务。运行记录显示全部活动任务与最近 100 条记录，旧文件仍保留在本机。

Windows 系统任务名称以 `LingxingSearch-Automation-` 开头；不同数据目录使用不同名称。启用后请保持应用目录位置不变；搬动目录后应重新启用定时运行。Mac 请先把应用放在固定位置，再启用；更新后若应用位置改变也需要重新启用。

本功能负责定时采集与结果留档，不自动判断经营好坏或推送消息。DSH 的判读脚本仍是独立参考文件。
