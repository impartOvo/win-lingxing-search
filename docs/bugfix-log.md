## 2026-11-14 · 自动化任务乱码与刷新问题

修复提交：[e863435](https://github.com/impartOvo/win-lingxing-search/commit/e863435cf8e86dfcab0283af7163a3062382b46e)。修复已同步至 `main`、`mac`，尚未单独发布新的正式安装包；应用版本字段仍为 `1.2.2`。使用时需核对安装包是否实际包含该提交。

### BUG-20261114-01：保存、编辑任务后中文乱码

**现象与影响**

在 Windows 自动化页面保存或编辑任务后，国家、筛选条件等中文可能变为乱码。损坏的内容已经写入任务配置，不是单纯的字体或显示问题。后续采集使用损坏的国家值，可能报“领星国家选项中未找到”，导致任务失败。

**原因**

Windows 界面通过标准输入向 Node 进程发送 JSON。原实现直接使用 `process.StandardInput.Write(...)`，发送端采用系统默认编码，而接收端将内容按 UTF-8 解析。在中文 Windows 默认代码页环境中，两端编码不一致会损坏中文字段。

原有界面自检主要确认任务条数、ASCII 查询值和运行时间，未逐字段核对中文国家、名称及店铺，因此没有检出这条实际保存路径中的错误。

**修改**

- 在 `desktop/Automation.cs` 的任务调用路径中，向标准输入底层流写入明确的、无 BOM 的 UTF-8。
- 保持既有任务 JSON 格式，覆盖名称、品名、国家和店铺等所有请求字段。
- 增加中文字段的保存、编辑和回填断言，不再仅以“保存成功、有一条记录”作为通过条件。

**验证**

- 使用合成中文任务名称、中文品名、中文店铺及中文国家，通过实际 Windows 界面调用路径保存。
- 核对落入任务数据的名称、品名、店铺、国家、标识类型和匹配方式，确认文字完整。
- 重新选择该任务，核对编辑器回填内容；更换中文国家并再次保存，确认修改后仍完整。
- 更新后的本机应用界面自检通过；修正本机受损任务后，两项真实任务并发采集成功，返回结果的筛选条件与任务一致。

**已有数据的处理**

修复阻止新的编码损坏，不会自动恢复所有旧版已写坏的内容。更新后应重新选择受损的国家或填写原查询条件再保存。本次本机配置在备份后，仅恢复了有明确依据的字段；未将真实配置或备份上传仓库。

### BUG-20261114-02：操作按钮约每 4 秒闪烁一次

**现象与影响**

“暂停定时运行”“同时运行全部启用任务”“立即运行选中任务”“删除选中任务”等按钮周期性变暗后恢复。刷新恰好发生在点击时，操作可能被忽略。表格重复重建也会干扰当前选择和编辑体验。

**原因**

原实现让每 4 秒一次的只读状态刷新复用修改操作的忙碌流程：刷新开始禁用按钮，结束后恢复；刷新占用忙碌标志时，新操作直接返回。每次响应还会重建任务和运行表格，即使内容未变化。

**修改**

- 将后台刷新状态与实际操作状态分开；只读刷新不再切换操作按钮的可用状态。
- 允许刷新期间提交保存等操作，用请求修订号识别并忽略过期的刷新响应，防止旧状态覆盖新操作结果。
- 比较任务和运行数据的内容，仅在数据变化时更新对应表格。
- 保留正常修改操作期间的按钮禁用，防止同一操作被连续重复提交。
- Windows 与 Mac 界面均同步上述刷新逻辑。

**验证**

- Windows 自检监听按钮的 `IsEnabledChanged`，确认纯后台刷新未产生可用状态切换。
- 确认数据未变化时，任务表格和运行表格继续使用原有数据源。
- 在编辑器输入尚未保存的中文内容，触发刷新，确认编辑未被覆盖。
- 在刷新尚未完成时提交保存，确认操作被受理且最终数据包含修改后的内容。

这些检查验证的是界面刷新与操作提交。后台刷新本身不是采集调度器；闪烁问题不能作为某次采集失败原因的替代证据，采集失败仍需核对对应日志。

### BUG-20261114-03：日期下拉框显示内部键值对

**现象**

采集日期范围显示为 `[yesterday, 昨天]` 等内部对象文字，而不是单独显示“昨天”。

**原因与修改**

Windows 自定义下拉框模板中，日期选项的选中展示未明确使用中文名称模板。为该控件增加绑定 `Value` 的 `ItemTemplate`，继续使用 `Key` 作为保存和执行时的选项值。

**验证**

Windows 自检检查实际选中项展示区域中的文本为“昨天”，同时任务仍保存为 `period: "yesterday"`，日期计算规则保持一致。

### 同次排查中的任务配置纠正

另一项失败任务将按品名查询的内容配置成了 FNSKU。该日志对应的是 Listing 未匹配到唯一 FNSKU，与中文编码问题分开核对。在使用者确认后，仅调整了相应本机任务的查询类型。

这不是新增的自动推断规则。程序仍按用户选择的标识类型执行，不会将未找到的 FNSKU 自动当作品名查询。

### 升级与回退

1. 使用包含修复提交的构建版本，保留自己的历史结果和登录目录。
2. 检查旧任务中是否已有乱码；如有，重新填写正确字段后保存。
3. 先立即试跑，再检查运行记录中的结果、筛选条件和日期。
4. 如需回退，先暂停定时运行并等待活动采集结束，再恢复备份的应用文件。回退程序不会自动恢复已损坏的文字，也不会自动移除系统定时注册。

`main0.9`、`mac0.9` 仍保留新增重置和自动化功能之前的旧版；这两条分支不是本次修复前一刻的配置备份。
