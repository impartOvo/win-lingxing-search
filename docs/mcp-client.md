# 领星 MCP 客户端

本功能在 1.4.0 开发版本加入。软件可以独立连接领星 MCP；日常采集无需打开 Codex，也无需调用大模型。浏览器采集继续保留。连接与数据权限以领星实际返回为准。

## 首次连接

1. 打开侧栏「MCP 连接」。本机 Codex 已配置名为 `lingxing` 的远程服务时，可点击「从 Codex 导入」。否则填写领星提供的 HTTPS 服务地址及密钥。
2. 认证头默认为 `X-Mcp-Key`；服务使用 Bearer 认证时选择 `Authorization`。连接方式保持 `auto`，也可按服务要求指定 HTTP 或 SSE。
3. 点击「保存连接」，再点击「测试已保存连接」。测试会独立验证连接、国家店铺查询和产品表现工具定义，不依赖聊天转发。
4. 返回「采集条件」，将通道改为「MCP 直接采集」，填写商品、国家、店铺和日期。币种默认按所选范围确定；跨币种范围需明确选择统一统计币种。

保存成功后密钥框会清空，密钥不回显。原地址和认证头不变时，密钥留空表示保留原密钥；更换地址或认证头需重新填写密钥。测试使用的是已保存连接，未保存的编辑不会用于查询。

## 商品与统计口径

- 品名先用 Listing 的本地品名查询匹配商品，按搜索方式作精确或包含匹配，取匹配行的父 ASIN 并去重，再读取父 ASIN 产品表现；可以覆盖同一品名下的多个父体。
- FNSKU 先解析为 MSKU；范围内无法唯一确定时停止并提示缩小店铺范围。
- ASIN、父 ASIN、MSKU、SKU、SPU 使用对应报告维度和搜索字段，建议输入完整标识。不会根据短词自动猜测类型。
- 明确发送起止日期、国家与授权店铺 ID，以及统计币种。产品表现使用下单日期口径，不套用接口默认人民币。
- 读取全部分页，校验匹配总数。接口错误、重复分页或没有匹配的产品记录均明确提示，不把空响应或缺失值解释为零销量。
- 库存是采集时的快照；历史广告和财务指标可能更新。对比两次采集时要核对采集时刻、店铺范围、父体归集与币种，不能仅凭历史日期相同认定所有字段应完全相同。

## 自动化任务

每项任务可以单独选择浏览器或 MCP 通道，以及 MCP 统计币种。旧任务没有通道字段时继续使用浏览器；导入或保存连接不会自动切换旧任务。编辑任务后点保存，后续执行使用新通道；已开始的任务不改变。

MCP 与浏览器共用已有按星期、时间触发的调度器。关闭主窗口后，MCP 任务使用软件保存的独立授权运行，不需要 Codex 或 Chrome 保持打开。同刻任务继续独立并发，不新增任务数或并发数上限；实际请求能力受服务和电脑资源约束。

实测领星可能对同一账号、同一工具返回 `429` 并发限制。客户端对此等待并逐步延长间隔重试，最多额外重试五次；只重试明确的服务限流，不自动重试认证失败、参数错误或其他业务错误。这样不会通过增加任务来绕过服务端限制，最终仍未成功时会如实记录失败。

## 结果及凭据

- MCP 每次保存 `results/mcp-标识.json` 和 `results/mcp-data-标识.json`，两份文件后缀一致。前者记录条件、来源、日期、解析结果及分页，后者保存完整业务响应。
- 原有 `browser-*.json` 结果继续可读；历史列表和结果页区分两种来源。成功记录在对应完整业务文件写入后发布。
- 连接存储在数据目录的 `.private/mcp/connection.json`。Windows 使用当前用户 DPAPI 加密密钥；迁移到其他用户或电脑后需要重新配置。macOS 使用权限为 `0600` 的私有文件，当前未集成 Keychain 加密。
- 从 Codex 导入只读取 `mcp_servers.lingxing` 的服务地址与受支持认证头，另存到软件数据目录，不修改 Codex 配置。导入后软件不再依赖该配置文件。
- 密钥不作为进程命令行参数传递，不写入业务结果和普通日志；Windows 的加解密通过隐藏进程的标准输入输出完成。不要公开 `.private/` 或含真实数据的 `results/`。

## 实现与开源参考

客户端使用 MIT 许可的 [官方 MCP TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk)，通过其 HTTP／SSE 传输和 Client 调用工具。仅允许 PulsarFetch 所需的三项只读工具：国家店铺选项、Listing 查询、产品表现查询。调用前执行领星要求的 `help → search → action`，核验只读类型并按实时 Schema 验证参数。

相关实现：`mcp/client.cjs`、`settings.cjs`、`collector.cjs`，以及根目录统一入口 `collector.cjs`。连接测试可参考官方 [MCP Inspector](https://github.com/modelcontextprotocol/inspector)。首次连接失败时，先检查服务地址、密钥权限、网络和服务支持的传输方式。
